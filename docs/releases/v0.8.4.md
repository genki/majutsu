# majutsu v0.8.4

clusterのbackend転送とwatch同期の競合を改善し、状態保存先の容量不足を検出するリリース。
v0.8.0〜v0.8.3の変更・修正も含む。

## 主な変更

- v0.8系ではmaster-localへのfsync完了後にslaveへACKを返し、S3/GCSへの転送を
  非同期の二次バックアップとして扱う。host別tokenと自prefixへのACLも追加している。
- backend転送はcontent・metadata・refの依存順序を守り、DELETE待機によるPUTの滞留を防ぐ。
  lag通知には、他の送信にブロックされていない最古itemを使う。
- master-localの保持・削除索引を改善し、backend公開とlocal GCの整合性を保つ。
- watchの同期起動を直列化し、保守処理との競合時は再送を延期する。
- deep検査は対象snapshotと同期状態を保存し、同期中の未公開objectを恒久欠損と誤判定しない。
- `health --json`に`state_volume`を追加する。状態保存先の空き5GiB未満または5%未満はwarning、
  512MiB未満はcriticalとし、取得失敗もwarningにする。Unix・WindowsのOS容量APIを使う。
- cluster通知hookの失敗を永続化し、指数backoffによって通知の過剰な再実行を防ぐ。
- Windowsのルート付きrestore filterの検査とエラーメッセージを統一する。
- Windowsでキュー・GC索引の更新と読込みが重なる場合の一時的な共有エラーを再試行する。
  恒久的なアクセス拒否やJSON破損は、引き続きエラーとして報告する。
- Windowsの通常パスと拡張パス表記をそろえ、`state`・`log`の作業範囲を正しく判定する。
  watchのメモリ上限もWindowsのOS APIで検査する。
- 公開用スクリプトが`cargo publish`の失敗を正しく返すよう修正し、失敗・再試行の回帰試験を追加した。
- MinIOのS3互換E2Eに、暗号化した状態のclone・fsck・restore比較を追加した。

## 互換性と更新

- cluster protocolはv2で、v0.8系のwire formatとACKの意味は維持する。
  `state_volume`は後方互換のJSON field追加である。
- protocol v1を使う旧版との混在は接続時に拒否する。v1から更新する場合はslaveを停止し、
  queueを保持したままmaster、slaveの順で更新する。
- 現在のsnapshotのdeep検査はmaster上の存在照合であり、全履歴の復号・復元検証とは区別する。

## 配布

正式版の表示は`mj 0.8.4`とし、開発版用の`+build.N`は付けない。

```sh
cargo install majutsu --version 0.8.4 --locked
```

Linux x86_64には以下を配布する。

- `majutsu-0.8.4-linux-x86_64.tar.gz`
- `majutsu-0.8.4-linux-x86_64.zip`
- `SHA256SUMS`

## 検証範囲

- Linux・macOS・Windowsのネイティブ環境でworkspaceのテストを行う。
  OS固有の修正後は、変更した経路も再検証する。
- Linuxではfmt・clippy・内部crateのミラー整合性と公開スクリプトの回帰試験を行う。
- File remoteとMinIOのS3互換remoteでは、暗号化した状態のclone・fsck・restoreと内容比較を行う。
- 配布用crateのdry-runビルド、公開後のregistryからのインストール、最適化済み配布物の
  `--version`・`--help`を確認する。
- GCS実環境、AWS S3、Cloudflare R2とcold-tier復元は、今回の候補で新たな実検証を行っていない。

実測した検証結果と配布物のチェックサムは
[GitHub Release](https://github.com/genki/majutsu/releases/tag/v0.8.4)に記録する。
